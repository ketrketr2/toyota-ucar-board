# UCAR SIGNAL｜中古車AI検索 タイアップ効果ボード

公開URL：https://ketrketr2.github.io/toyota-ucar-board/ （ID とパスワードで開きます）
9月の版：https://ketrketr2.github.io/toyota-ucar-board/v05/

## 自動更新（.github/workflows/ucar-refresh.yml）
- 1日5便（07:12・08:40・11:47・14:17・18:05、日本時間）で、計測データ（ketrketr2/toyota-geo-board）からボードのデータを作り直します。データに変化がない便は何もしません。
- GitHub の予約起動は混雑時に数時間遅れることがあるため、便を分散して置いています。
- 点検（tools/check.py）に通った版だけを公開します。通らないときは公開せず、前の版を残したまま Issue でお知らせします。同じ内容のお知らせは繰り返しません。
- 計測日の前日は、その日の便で【予告】の Issue を出します（同じ日の予告は1回だけ）。
- お知らせは GitHub の通知（メール）で届きます。Slack にも送るときは、Settings > Secrets and variables > Actions に SLACK_WEBHOOK_URL を登録します。

## 鍵のしくみ
- 画面（gate/app.json）とデータは暗号化してあり、閲覧時の ID とパスワードで開きます。
- 自動更新は公開鍵（gate/pub.pem）だけでデータを暗号化します。パスワードと秘密鍵は、このリポジトリにも自動更新の環境にも置きません。

## 答えの正確さの点検（tools/factcheck.py）
- AIの答えを1文ずつ読み、トヨタ認定中古車についての7つの項目（ロングラン保証の期間・走行距離、保証修理の拠点の数、中古車ハイブリッド保証、車両検査証明書を作る人、ブランドの名前、クリーニングの工程）を、トヨタの公式サイトの説明と照らします。結果は総覧の「答えの正確さ」に出ます。
- 公式の説明は 2026-11-10 に各ページで確かめた内容です。公式の説明が変わったら、factcheck.py の FACTS と判定の規則を直します。

## PDFレポート（画面上部の「PDFレポート」）
- タイアップの効果に絞った、A4横・9ページの資料にします（タイアップの効果、効果の道筋、3媒体の役割、記事の狙い目、効果の判定、記事が参考元に使われるか、検索全体への広がり、記事で正したい説明、日程と次の計測）。
- ページごとに結論・図・コメント3つ。数字とコメントは、開いた時点のデータから作り直します（自動更新に合わせて変わります）。掲載後の計測が入ると、表紙と「効果の判定」は掲載前との差と判定に切り替わります。
- 「PDFとして保存」を押すと印刷の画面が出ます。送り先で「PDFに保存」を選びます（用紙はA4横に設定済み）。

## 検索数
- 質問と検索の語の検索数は、Google 広告の月の検索数（日本・日本語）です。84問は toyota-geo-board の data/ucar/volumes_2026-10-26.json、検索1,761本は data/ucar_signal/volumes_2026-10-19.json を使います。
- Google の集計に数字が出ない語は「数字なし」と表示します（0回とは書きません）。
- トップのマスの右下の印、総覧の「検索の多い質問」、質問の作り方、2-2、PDFレポートの「記事の狙い目」に出ます。KPIの割合は、検索数に関係なく質問1つを同じ重さで数えます。

## 掲載が始まったら
- tools/rounds.json の publish_start に、最初の記事の掲載日（YYYY-MM-DD）を書きます。その日以降の計測を「掲載後」として数え、ボードの見出しと判定が自動で掲載後の比較に切り替わります。
