## 自動更新（.github/workflows/ucar-refresh.yml）
- 1日5便（07:12・08:40・11:47・14:17・18:05、日本時間）で、計測データ（ketrketr2/toyota-geo-board）からボードのデータを作り直します。データに変化がない便は何もしません。
- GitHub の予約起動は混雑時に数時間遅れることがあるため、便を分散して置いています。
- 点検（tools/check.py）に通った版だけを公開します。通らないときは公開せず、前の版を残したまま Issue でお知らせします。同じ内容のお知らせは繰り返しません。
- 計測日の前日は、その日の便で【予告】の Issue を出します（同じ日の予告は1回だけ）。
- お知らせは GitHub の通知（メール）で届きます。Slack にも送るときは、Settings > Secrets and variables > Actions に SLACK_WEBHOOK_URL を登録します。

## 鍵のしくみ
- 画面（gate/app.json）とデータは暗号化してあり、閲覧時の ID とパスワードで開きます。
- 自動更新は公開鍵（gate/pub.pem）だけでデータを暗号化します。パスワードと秘密鍵は、このリポジトリにも自動更新の環境にも置きません。

## 答えの正確さの点検（tools/factcheck.py）
- AIの答えを1文ずつ読み、トヨタ認定中古車についての7つの項目（ロングラン保証の期間・走行距離、保証修理の拠点の数、中古車ハイブリッド保証、車両検査証明書を作る人、ブランドの名前、クリーニングの工程）を、トヨタの公式サイトの説明と照らします。結果は総覧の「答えの正確さ」に出ます。
- 公式の説明は 2026-11-10 に各ページで確かめた内容です。公式の説明が変わったら、factcheck.py の FACTS と判定の規則を直します。

## PDFレポート（画面上部の「PDFレポート」）
- タイアップの効果に絞った、A4横・9ページの資料にします（タイアップの効果、効果の道筋、3媒体の役割、記事の狙い目、効果の判定、記事が参考元に使われるか、検索全体への広がり、記事で正したい説明、日程と次の計測）。
- ページごとに結論・図・コメント3つ。数字とコメントは、開いた時点のデータから作り直します（自動更新に合わせて変わります）。掲載後の計測が入ると、表紙と「効果の判定」は掲載前との差と判定に切り替わります。
- 「PDFとして保存」を押すと印刷の画面が出ます。送り先で「PDFに保存」を選びます（用紙はA4横に設定済み）。

## 検索数
- 質問と検索の語の検索数は、Google 広告の月の検索数（日本・日本語）です。84問は toyota-geo-board の data/ucar/volumes_2026-10-26.json、検索1,761本は data/ucar_signal/volumes_2026-10-19.json を使います。
- Google の集計に数字が出ない語は「数字なし」と表示します（0回とは書きません）。
- トップのマスの右下の印、総覧の「検索の多い質問」、質問の作り方、2-2、PDFレポートの「記事の狙い目」に出ます。KPIの割合は、検索数に関係なく質問1つを同じ重さで数えます。

## 表示する計測（日・期間）の切り替え（v15・カレンダーは v15.2）
- 画面上部の「計測」ボタン（カレンダーの印）と、1〜3章の見出しの札から開きます。「掲載前の平均」「掲載後の平均」「最新の計測」のボタンか、カレンダーで選びます。
- カレンダー：計測した日（84問を3回ずつ聞いた日）には枠と数字（重点31問の率）が付きます。その日を押すとその日の値、続けて別の日を押すと、2つの日の間にある計測の平均になります。計測のない日から始めても選べます（間に計測がないときは選ばずに知らせます）。
- カレンダーの印：白抜きの丸＝日ごとの確認（平均には入れない）、金の帯＝記事の掲載期間（1・2月の予定）、丸囲みの日付＝今日、青い帯＝表示中の日・期間。PCは2か月、スマホは1か月を並べ、‹ › で月を送ります。キーボードでは矢印で日を動かし、Enter で選びます。
- 既定は、掲載後の計測があれば「最新の計測」、なければ「掲載前の平均」です。
- 選んだ日・期間に合わせて変わるのは、総覧（ヒーロー・KPI）と 1〜3章の値・図・表です。判定の基準（掲載前の平均）・効果ありの線・2-3「効果の判定」は、選んだ期間に関係なく掲載前で固定します。
- 検索1,761本（4章）は計測した日の1回、GA4（5章）は月ごとの集計のため、この切り替えの対象外です。PDFレポートも、基準は掲載前の平均、比べる相手は最新の計測で作ります（選んだ期間に左右されません）。
- 日ごとの確認（1回だけ聞いた計測）は、期間の平均には入れません（1-1 の推移と 2-4 では見られます）。

## 推移で比べる（時系列・v15.3）
- 2点（掲載前→選んだ日）だけで比べていた図を、すべての計測の日を並べた推移の図にしました：1-1 図1-2・1-3（AIごと）、1-3 図1-11（検討の段階ごと）、2-1 図2-3（媒体ごと：記事で答える10問と、媒体のページが参考元に出る割合）、3-1 図3-2（最初に名前が挙がる店）。
- どの推移の図も、青い帯が表示中の日・期間、右の薄い帯がこれから測る時期です。回の点を押すと、その日の計測で総覧・各画面を表示します（カレンダーで選ぶのと同じ）。白抜きの点は日ごとの確認（1回だけの計測）で、表示の切り替えには使いません。
- 段階ごと・媒体ごとの図は、媒体（段階）ごとに小さな図を並べ、掲載前の平均（点線）と効果ありの線（緑の破線）を引いています。縦の目盛りは並べた図でそろえています。媒体の掲載日を登録すると（tools/build_data.py の ARTICLES の date）、その媒体の図に縦の線が出ます。
- GA4（5-1 図5-3）：AIからの訪問の日ごとの推移に、表示中の期間（青）と、その前の同じ日数（灰）を重ね、1日平均とChatGPTの割合を比べます。選んだ期間が7日より短いときは、終わりの日までの7日で比べます。
- PDFレポートに「計測の推移」のページ（5ページ目）を加え、10ページにしました。重点31問と比較用30問・検討の段階（媒体）ごと・AIごとの推移と、回ごとの値の表（直近6回・掲載前の平均・最新−掲載前）を載せます。表紙の道のりの図にも、掲載後の回が入ります。

## 記事のURLで探す（2-4・v15）
- 記事・動画のURLを入れると、そのページがAIの答えの参考元に出た回数を、計測の日・質問・AIごとに数えます。数える範囲は「このページ」「この階層」（URLの最後の / まで）「サイト全体」から選べます。本文に媒体の名前が出た答え（言及）も数えます。
- データは tools/cindex.py が自動更新のたびに作ります（data の cix）。84問の計測（回・日ごとの確認）と検索1,761本の、すべての答えの参考元URLを正規化して持ちます。計測が増えると、登録済みのURLの数字も自動で更新されます。
- URLの正規化：http・https、www、ポート番号、#以降、末尾の「/」と index.html、utm_ や padid などの追跡用の文字を区別しません。日本語を含むURLは、エンコードの有無を区別しません。画面側（JavaScript の nurl）と cindex.py の nurl は同じ決まりです。片方を直すときは両方を直します。
- 「登録したURL」は、見ている人のブラウザに保存されます。チームで同じ一覧を見るときは「一覧を共有（リンク）」か、書き出したCSVを渡します（読み込みでも取り込めます）。共有リンクを開くにも ID とパスワードが要ります。
- 「今回の記事」は tools/build_data.py の ARTICLES、「前年の記事」は ART25 の一覧です。前年の記事のURLは、既知のURLと、参考元の題名・サイトで照らしたものです。

## 掲載が始まったら
- tools/rounds.json の publish_start に、最初の記事の掲載日（YYYY-MM-DD）を書きます。その日以降の計測を「掲載後」として数え、ボードの見出しと判定が自動で掲載後の比較に切り替わります。
- 記事が公開されたら、tools/build_data.py の ARTICLES に、その記事のURL・題名・掲載日を書きます。KPI①（記事引用率）に入り、2-4「今回の記事」にも結果が出ます。

## 記事チェック（check/・v15.4）
公開URL：https://ketrketr2.github.io/toyota-ucar-board/check/ （ボードと同じ ID とパスワードで開きます。ボードの目次（2 タイアップの効果）の「記事チェック」からも開けます）
- 媒体の原稿（Word のファイル、Word・Google ドキュメントからのコピー、テキスト）を入れると、AI 検索（AI Overviews など）に引用される形かを判定し、媒体に戻すコメント（コピー・テキスト・CSV）まで作ります。段階は構成案・初稿・最終稿・公開後から選びます。
- 判定は、機械の点検（形・数字・正式表記・PR 表記など）と、Claude の判定3本（担当の質問と中身／直す点と誤字脱字／数字と正式表記の照合）を合わせて出します。Claude は Claude Opus 5.5（使えないときは Claude Sonnet 5.5）を、見ている人のブラウザから Claude の API で呼びます。
- 画面（check/index.html）は、ボードと同じ公開鍵で暗号化してあります。画面を直したときは、手元で組み立てて暗号化し、check/index.html だけを置き換えます（平文の画面は置きません）。

### Claude の鍵（.github/workflows/check-key.yml）
- 鍵は Settings > Secrets and variables > Actions の ANTHROPIC_API_KEY にだけ置きます。check-key（2時間ごと。Actions > check-key > Run workflow ですぐにも）が、ボードの公開鍵で暗号化して check/key.json に置きます。鍵が変わったかは指紋（check/key_fp.txt）で見ます。
- 入口で ID とパスワードから開いたときだけ、画面が鍵を使えます。鍵は記事チェック専用にし、Claude Console のワークスペースで月の上限を決めておきます。
- 鍵を替えるとき：ANTHROPIC_API_KEY を新しい鍵で上書きし、check-key を動かします（または次の便を待ちます）。古い鍵は Claude Console で無効にします。
- 鍵がない間・使えない間は、機械の点検だけで判定し、画面の帯で理由を知らせます。

### 記録と原稿の扱い
- 判定の記録（点数と、指摘の60字までの抜き出し）は、見ている人のブラウザに残します（［これまで］）。ほかの人やパソコンと分けるときは［記録を書き出す］→［記録を読み込む］。
- 書きかけの原稿は、そのタブを閉じると消える場所に置きます。原稿は判定のためにだけ Anthropic の API に送ります。
